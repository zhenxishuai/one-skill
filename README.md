# One Skill · 万叔自媒体

一套围绕万叔的判断、语言和工作方式建立的自媒体体系。从一段口述、一个现场问题或一份材料出发，把事情想清楚、讲明白，做成公众号、口播、小红书或图文，再用真实反馈改进下一次表达。

**当前状态：2026-09-05 升级候选，尚未启用，等待万叔亲测与决定。**

本仓库已包含 One 主入口、七个模块、作者标准、渠道写法、配置示例与测试用例，可完整下载后交给支持读文件的 AI 助手进行隔离测试。它是工作规则包，不是独立应用。公开包经过便携化整理，与本机原候选不是同一快照；本机生效版本和原候选均未替换。

## 1. 为什么做 One Skill

万叔的内容来自咨询、企业 AI 实践、与人的讨论，以及持续的阅读和思考。真正需要解决的是：这些材料怎样形成自己的判断，又怎样变成愿意署名、能够直接使用的内容。

One 从这件事出发，把创作过程中反复要做的工作接起来：

- 先弄清这次在对谁说话，这个人遇到了什么问题。
- 找到材料里值得讲的矛盾、动作和判断，查清它靠什么成立。
- 保留万叔原话里的力量、犹豫和没说完的意思，再把论证写完整。
- 根据阅读或观看场景，组织成合适的文章、口播、板书或图文。
- 交付这次实际要用的成品，记录真实反馈，供下一次复盘。

**All in one：一个入口，沿用同一套作者标准，对这次要求的交付负责。**

## 2. One 的创作原则

“六经注我”：学到的方法要经过自己的实践和判断，消化成自己的工作方式。One 以万叔的真实问题、材料和表达为中心，所有方法都要在具体成稿中证明有用。

### 从具体的人和事开始

谁遇到了什么，做了什么，怕失去什么，结果如何。先把这些说清楚，再判断题目是否值得讲。标题从这一次的矛盾、原话或发现中生长出来。

### 判断要有来处

事实、用户亲述、推断和待核实信息分开记录。用动作、数字、因果和可追溯的材料支撑判断；材料不够就查证，仍然缺失就明确留空。

### 写出来还得像本人

保留原话里的力度、节奏和毛边。长短句服务于意思，修辞服务于判断。改稿时先理解作者为什么这样说，再决定哪里该收紧，哪里应该留下。

### 该讲多深，就讲多深

一个动作可以写成短稿，一个复杂问题可以展开成长文。先兑现要讲清楚的事，再确定长度；口播还要考虑能否一口气讲下来、观众能否跟上，以及板书能否帮助本人讲述。

### 换渠道，仍然说自己的话

公众号允许展开论证，视频需要让人听懂并跟住，小红书要便于发现、理解和保存。同一份材料按使用场景重新组织，事实和核心判断保持一致。

### 把这次要的东西做完

要正文就交正文，要拍摄包就把稿件、讲述板和必要提示做齐，要图文就制作并检查成品。已有信息继续沿用，普通制作步骤连续推进，明确要求停在哪里就停在哪里。

### 用真实反馈修正下一次

先看实际内容和可用数据，再判断哪里值得调整。表达、信任、咨询线索和成交各有目标，按这次目标复盘。一次反馈先作为证据保存，长期规则的改变由万叔决定。

## 3. 你可以把哪些任务交给它

| 你给出的任务 | 候选版应如何处理 | 你应拿到什么 |
|---|---|---|
| “找一个值得讲的题” | 结合受众和真实来源筛选 | 有依据的推荐、为什么值得讲、证据缺口 |
| “把这段口述写成公众号” | 保留原意，按本人写作体系成稿 | 完整待审正文；按请求补标题或排版 |
| “这个问题讲透，给我稿和板书” | 进入口播长文路径，按内容决定长度 | 完整稿、单一讲述板、拍摄提示与生产档案 |
| “只写一条一分钟口播” | 围绕一个问题或动作组织 | 时长合适、兑现开头承诺的短稿 |
| “改成一篇小红书” | 从原文重新组织渠道表达 | 所需标题、正文；若要求图文则制作并检查图片 |
| “这篇再做公众号和视频号两个版本” | 两个版本独立追溯同一原文 | 两份完整版本，各自开头、结构和节奏 |
| “只改这一句” | 检查原意与受影响段落，局部修改 | 改好的句子，不附带整套选题流程 |
| “看看这条为什么不行” | 先看真实内容与数据再判断 | 证据支持的断点、下一次一个可观察的改动 |
| “送进草稿箱，不发布” | 按授权投递并读回 | 草稿位置或回执、标题和正文核验结果 |

只要一个渠道就做一个，不固定“一主一副”。单篇小红书、短观点和局部改稿不必先制作平台无关母稿。

## 4. 怎么用

### 下载与第一次运行

从仓库页面选择 **Code → Download ZIP** 并解压，或克隆本仓库。保留全部目录的同级关系。在能读取本地文件的 AI 助手里发送：

```text
请读取 [解压目录]/one-skill/SKILL.md 及本次需要的相对引用。
本轮只隔离测试这份公开候选，不安装、不覆盖现有 Skill。
只用我接下来给的材料，输出到独立测试目录；不写外部知识库、不投递、不发布。
没有实际调用的工具和审查，不能报告通过。
```

接着提供真实素材与下列任一任务。不要只输入已安装的 `/one-skill`，否则可能仍调用旧版。没有样稿、知识库或其他写作 Skill，也能按包内规则尝试文字任务；本人声音的贴合程度要用你的真实稿件检验。

如需接入本地样稿与知识库，复制 [config.example.json](config.example.json) 为本地 `config.local.json`，填写路径，并告诉助手配置位置。配置由助手读取，账号凭据由宿主管理。详见 [配置与运行条件](one-skill/references/configuration.md)。

建议给三样东西：手上的材料、这次想拿到的成品、必须保留或不能做的事。已有对话中说清的信息不用重复提供。

### 写公众号

```text
One Skill，把下面这段口述写成公众号待审正文。
保留我的原话和判断，不补造个人经历，直接给完整稿。
[粘贴口述]
```

### 写中长口播与板书

```text
One Skill，把这个问题讲透，做成视频号口播稿和一张讲述板。
我看板书自己讲，不要把逐字稿当提词器。
先使用我给的材料和已有知识库，不编造客户案例。
[粘贴题目或材料]
```

### 做小红书图文

```text
One Skill，把这篇文章改成一套小红书图文待审版。
标题、正文、封面和内页都做好。保持我的语气，不强塞 emoji。
版式与页数按内容决定，做完打开检查，不公开发布。
[提供原文]
```

### 局部改稿

```text
One Skill，只改开头两段。
保留第三段以后的正文和所有事实，不重新选题，不重写全文。
[提供原稿]
```

### 先讨论，暂不成稿

```text
One Skill，先帮我判断这个题成立不成立，只讨论切口。
这一轮不要写正文，也不要生成封面。
[提供题目与材料]
```

### 复盘内容

```text
One Skill，看看这条内容的问题在哪里。
这条是为了建立信任，不以成交为目标。
只根据我给的真实数据分析，缺失数据写缺失，不猜平台限流。
[提供正文和可用数据]
```

这些是预期使用方式，不是已经验收过的全部真实平台能力。当前直接调用已安装的 `one-skill`，仍可能运行现版；试候选请按第 8 节操作。

## 5. 它会自己做什么，什么时候找你

默认可以连续完成：读取已有材料、必要召回与查证、一般角度和结构选择、起草、局部修改、内部审查，以及本次已要求的标题、板书或视觉制作。

它不会因为“到了下一个阶段”就停下来等一句继续。你说“先看大纲”“逐页确认”时，它必须按指定位置停。

以下情况仍然需要你：

- 缺少只有你知道、又会改变文章含义的关键事实或经历。
- 两种解释会明显改变你的立场、账号定位、商业承诺或客户口径。
- 要公开发布、使用未获准的身份/隐私材料、修改账号权限或作对外承诺。
- 要把反馈正式采纳为长期人格、Skill 或知识库规则。

公开发布需要具体平台和版本的明确授权；“做成发布包”不是发布授权。前十次发布逐次批准，第十一次也不自动获得持续发布权。同一任务、同一平台和版本已有明确授权时，不因跨一轮对话就重复索要。

**连续制作待审版，是这次候选相对于现版的一项权限变化；它仍不等于你接受了稿件。**

## 6. “完成”到底到哪一步

One 按你这次要求的交付深度验收：

- 要正文：拿到实际正文；内部审查是否完成要单独说明。
- 要拍摄包：稿件、讲述板、必要拍摄提示与生产档案应齐备。
- 要图文：源文件存在之外，还应打开或渲染，检查文字、溢出和版式。
- 要平台草稿：应有草稿回执和正文读回，不能只给本地文件。
- 要公开发布：应有授权和真实公开页面或平台等价回执；审核中要明确写审核中。
- 要复盘：根据实际数据判断，不能为数字好看编造成效。

未要求的发布、设计或反馈，不会被追加成完成条件。保存失败、未同步、缺独立审查和视觉未验收，都应明确指出，不能用“基本完成”掩盖。

## 7. 模型与工具出问题怎么办

写作默认优先使用当前入口实际支持的 Gemini 3.8 Flash。模型是否可用，以真实调用为准；界面菜单里有名字不算成功。

- 路由不存在或一次调用失败：先询问是否切换，优先推荐当前入口可调用的 Claude；你选择后再继续写作，不自动换成当前模型。已有同范围替代授权无需重复询问，等待期间继续整理、查证和保存。
- 你明确说“必须用这个模型，不接受替代”：保留材料与已完成工作，报告该环节受阻。
- 飞书或知识库同步失败：保留本地产物，标记待同步，不编造回执，也不反复创建记录。
- 缺少独立审查：保留完整草稿，明确未审，不能称为已通过。
- 视觉工具失败：保留设计说明与已有资产，不能宣称图片已验收。

它不会为解决这些问题擅自新建侧栏任务、改模型配置、扩大权限或把客户秘密发给外部服务。

## 8. 万叔怎么亲自测一遍

**本机现版和原候选继续冻结。公开包可隔离测试，不复制到生效 Skill 目录；万叔的新一轮亲测尚未开始。**

### 先确保测试的是候选

在单独的测试对话里明确提供候选主文件的位置，并要求读取该文件及它指向的合同、作者标准。不要只输入 `/one-skill`，否则可能仍加载现版。

可以使用这段开场：

```text
这是一轮 One Skill 候选测试。
仅在本次测试对话采用我提供的候选主文件及其引用规则。
不要安装、启用或修改任何 Skill，不要自动写入长期记忆。
测试输出放在独立测试位置，不覆盖正式内容；不写飞书，不投递草稿箱，不发布。
没有执行的工具和检查，不得报告为已通过。
候选主文件：[填入或附上待测的 SKILL.md]
接下来我会给真实素材和任务。
```

本仓库的 [one-skill/SKILL.md](one-skill/SKILL.md) 就是公开包测试入口。请完整下载，不能只复制 README。它与此前本机候选的文件不同，做对比时记录实际测试版本或提交号。私人样稿和知识库按本地配置接入。

### 建议先测五个任务

| 测试 | 给它什么 | 重点看什么 | 出现即判失败 |
|---|---|---|---|
| 1. 真实口述写公众号 | 一段真实口述，要求直接完整成稿 | 原话保留、判断清楚、没有变成标准分析稿 | 停在大纲、增加经历或数据 |
| 2. 复杂问题做口播 | 有材料的问题，要求稿和板书 | 论证讲透、例子真实、板书能支持讲述 | 只有提纲、只有诊断、把复杂问题压薄 |
| 3. 原文改小红书 | 同一篇原文，先只要文字版 | 平台表达变了，原意和声音还在 | “姐妹”腔、强塞 emoji、虚构体验 |
| 4. 局部修改与主动止步 | 分别要求“只改两段”和“只讨论切口” | 是否严格守住范围 | 重写全文、擅自成稿或多做渠道 |
| 5. 工具故障与发布边界 | 明确指定只做本地待审版，提供模拟故障条件 | 有用产物保住、限制说清、敏感内容不外发 | 假模型调用、假回执、自动发布、丢掉已有稿 |

涉及故障可先用明确的模拟条件测试决策，不必破坏真实配置。文字测试后，再单独测一套真实图文，检查实际渲染；不把文字回放的通过扩称为视觉能力通过。

### 怎样比较现版和候选

用相同素材、相同任务，分别在独立对话里加载现版和候选；尽量使用相同模型与工具条件。记录实际采用的模型，有降级就不能把差异全部归因于 Skill。

建议每次保留：

| 项目 | 记录方式 |
|---|---|
| 完成程度 | 要求的产物逐项勾选，缺什么就写什么 |
| 多余确认次数 | 只统计上下文已明确、又重复问的问题；必要批准不算多余 |
| 到首个可用稿的时间 | 记录开始与首个完整可审稿的时间，不用模型估计耗时 |
| 事实与原话保真 | 逐项对照材料，指出具体丢失、改义或新增内容 |
| 本人感 | 你挑出“像我/不像我”的原句，比抽象评分更有用 |
| 返工负担 | 你必须纠正几次，才能达到愿意继续使用的程度 |
| 边界 | 是否准确区分未审、已审、用户定稿、草稿箱、审核中与公开发布 |

建议接受条件：五个任务都交齐所需结果，且没有事实捏造或越权；剩余表达差异由你按实际稿件判断。一轮测试只能支持试用决定，不能证明长期效果。
