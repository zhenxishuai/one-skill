# One · 万叔的内容判断与制作

**两套可以单独用的 Skill，一个可选总入口。**

内容判断帮你把话想清楚；内容制作帮你把确定要做的东西做好。你可以只用其中一套，也可以让 One 接起来，完成从材料到成品的任务。

当前为 **2026-09-05 公开候选**，供下载和隔离测试。本机已安装版本未替换，正式启用仍待亲测与批准。它是一套 AI 工作规则，运行需要支持读文件的助手和相应工具。

## 两套分别做什么

| 入口 | 适合交给它的事 | 你应拿到的结果 |
|---|---|---|
| [内容判断 · one-judge](one-judge/SKILL.md) | 判断选题价值、信息密度、论证、证据，讨论没想清楚的地方，复盘内容 | 有依据的判断、具体问题、该保留和该补的部分 |
| [内容制作 · one-produce](one-produce/SKILL.md) | 起草、改稿、渠道改编、口播板书、生图、排版、已授权投递发送 | 这次要求的实际稿件、图片、排版文件或真实回执 |
| [One · one-skill](one-skill/SKILL.md) | 不想挑入口，或需要把判断和制作连起来 | 按任务分流，沿用材料和决定，连续完成已授权工作 |

判断侧关注：这件事对谁有用、你到底想说什么、凭什么成立、每段有没有新增信息、是否像本人会说的话。它不会把内部检查变成一长串问卷，也不会因为自己觉得题目普通就否决你的制作要求。

制作侧接住已有想法或定稿。只要排版就保留正文，只要封面就做封面；要公众号和小红书两个版本就交两份。普通编辑直接做，遇到需要改变立场或补关键事实的问题，才局部交回判断侧。

两套沿用万叔的作者标准：真实材料、具体动作、有来处的判断，保留原话里的力度和毛边。学到的方法消化成自己的工作方式，用实际成品检验。

内部方法也按职责拆开：判断侧把抽象词还原成具体情境，核对前提和证据，给出能成立的说法；制作侧把采用的材料放进具体段落，保持同篇声音一致，再做文字、讲述和成品检查。共同论证底稿不再自动写文章。

## 制作侧可以接哪些能力

| 能力 | 包内已有的做法 | 真实执行条件 |
|---|---|---|
| 公众号、口播、板书、小红书文字 | 作者标准、渠道写法、编辑与改编规则 | 可用写作模型；本人样稿可选 |
| 小红书封面与图文内页 | 封面重点、逐页内容、系列一致性、文字与缩略图检查 | 生图/设计工具、文件与视觉检查能力 |
| 公众号封面与正文配图 | 裁切检查、插图用途、事实与示意图的区别 | 生图/设计工具、实际预览 |
| 公众号排版 | 保留原文、静态 HTML、手机阅读与复制检查 | 文件/浏览器工具；平台效果需进入实际编辑器检查 |
| 投递草稿箱 | 核对账号与稿件版本、投递后读回 | 平台连接及该次授权 |
| 发送文档或消息 | 核对接收对象、内容、发送结果；不把已发送说成已读 | 可用连接器/浏览器及明确发送授权 |

**规则随包提供；模型、账号连接和工具不随仓库附送。** 没有生图工具就不能称已生成图片，没有平台连接就不能称已投递。完整 [能力目录](one-produce/references/capabilities.md) 说明每项条件。

以后增加视频剪辑、其他平台排版或新的发送方式，只在制作侧增加相应操作说明和验证案例。总入口和判断侧无需加入这些平台细节。已有专项 Skill 可选绑定，按需读取；没有绑定也可按包内做法使用宿主现有工具。

## 怎么用

下载完整仓库并解压，保留目录的同级关系。三个入口共享包内规则，所以不能只复制一个 SKILL.md。无需先安装。

在能读取本地文件的 AI 助手里，按实际需要发送：

```text
读取 [解压目录]/one-judge/SKILL.md 和本次必需引用。
本轮隔离测试，不安装或覆盖已有 Skill。
帮我判断下面这个题有没有值得讲的东西，只讨论，不写正文。
[材料]
```

```text
读取 [解压目录]/one-produce/SKILL.md 和本次必需引用。
本轮隔离测试，产物存独立测试目录，不发送、不发布。
这是定稿，保留正文，做公众号封面与排版；做好后打开检查。
[定稿]
```

```text
读取 [解压目录]/one-produce/SKILL.md 和本次必需引用。
把下面材料做成小红书图文待审版，正文、封面和内页都做好。
页数按内容决定，保留我的语气。不要公开发布。
[材料]
```

```text
读取 [解压目录]/one-skill/SKILL.md 和本次必需引用。
先检查这个观点和证据，再直接写出公众号完整待审稿。
已有信息继续沿用；只问会改变意思、又只有我知道的问题。
[材料]
```

直接输入已安装的 `/one-skill` 可能仍调用旧版；测试时明确给出这份候选文件路径。指定只讨论、先看大纲或逐页确认时，按你要求的位置停下。

## 接入自己的工具与材料

复制 [config.example.json](config.example.json) 为本地 `config.local.json`，告诉助手其位置。可以填入已授权的作者样稿、知识库路径、输出目录，以及 `production_skills` 中对应专项 Skill 的路径。配置由助手读取，不是自动安装程序。

私人材料、密钥和账号凭据不放入公开仓库。填写连接名称不等于授权发送。详见 [配置与运行条件](one-skill/references/configuration.md)。

内容起草和实质改写偏好 Gemini 3.8 Flash；纯判断、定稿排版、生图或发送无需因此切换写作模型。指定模型不可用时先询问，推荐当前入口实际可调用的 Claude，获得选择后继续；同范围的既有替代授权无需重复询问。没有真实调用就不声称使用了某个模型。

## 什么时候会问你

一般制作连续推进，已经讲清的信息不反复确认。只有缺少会改变含义的本人事实、重大立场或商业承诺选择，以及缺失的必要授权，才需要你决定。

发送、投递草稿和公开发布分别按明确授权执行。请求“做成发布包”不等于允许发布；公开发布需明确平台与版本，前十次逐次批准，第十一次也没有自动持续权限。同一范围已有授权不重复问。隐私、账号权限与对外承诺边界保持有效。

这次调整允许制作侧独立连续做成品，不再默认先经过价值审问；它没有新增公开发布、对外发送或账号修改权限。判断建议也不代替用户定稿。

## 怎样检查它是否好用

先用 [五个测试用例](one-skill/references/case-pack.md) 检查范围、交接、制作能力和授权边界，再换成你的真实素材亲测。记录实际产物、额外确认次数、事实与原话变化、缺口和必须返工的地方。模拟故障与真实工具执行分开记录。

在仓库根目录运行 `python3 scripts/check_package.py`（Python 3.9+）可检查公开规则文件、引用和配置示例，跳过本地私人配置及输出目录；上传前仍需检查实际 Git 跟踪文件，忽略规则不自动移除已跟踪资料。结构通过不证明文稿好、生图成功或平台已经接通。当前证据与未执行项见 [验证记录](one-skill/references/review.md)。

完成按你本次要求判断：文字要有实际稿件；图片要打开检查；排版要区分本地预览与平台编辑器验收；发送要有真实回执；公开发布要有公开页面证据。未执行的部分直接写明。
