# One · 把内容想明白，做出来

这是候选规则包，读取与隔离测试不等于安装或启用。总入口保持轻量，平台细节留在制作侧按需读取。

## 分流

先读 [共同约定](references/operating-contract.md)，从已有材料判断本次交付，已有信息不重复问。

| 用户要什么 | 去哪里 | 交什么 |
|---|---|---|
| 审题、看价值/密度、检查论证、复盘 | [内容判断](../one-judge/SKILL.md) | 有证据的判断、必要修正或明确要求的论证稿 |
| 写稿、改编、排版、生图、发送已有内容 | [内容制作](../one-produce/SKILL.md) | 指定成品或真实投递回执 |
| 从模糊想法做到指定成品 | 判断 → 制作 | 足够支持起草就连续完成，无默认阶段确认 |
| 只改一句、只排版、只发送指定文件 | 直接制作 | 只完成授权部分，不重审内容价值 |

“先讨论”不成稿；“内容定了”不重做价值审查。已有立场和材料足够的完整写稿，直接制作，不强制先判断或先母稿。只加载本次所需入口及引用，不把全文交给所有模块。

## 衔接与完成

用 [轻量交接](references/handoff.md) 沿用已有材料、批准与停止位置，不让用户填表。一次一个主步骤，完成后继续本次请求内的下一步。模块返回调用者，独立入口可直接交付，禁止无条件互相转交。

最终回读指定产物与证据：稿件、图片、平台草稿、已发送和公开分别报告。工具缺失保留已有成果，标缺口，不给假回执。按 [验收标准](references/validation-rubric.md) 检查本次范围；升级用 [用例](references/case-pack.md)。
