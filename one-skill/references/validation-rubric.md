# One 验收标准

验收只覆盖本次用户要求的交付深度。不是所有内容都需要母稿、视觉、平台草稿、公开发布或反馈；不适用项明确写 N/A，不计为失败。禁止使用固定总分强迫所有路径跑全流程。

| 检查 | 通过证据 | 阻断或返工条件 |
|---|---|---|
| 范围与执行 | 实际产物满足完整稿/局部改/只讨论/指定渠道数量 | 停在诊断或交接提示词；擅自扩平台或只大纲请求却成稿 |
| 作者与原意 | 对照原文、保留项、本人样本；候选观点有标记 | 捏造本人立场/经历；外部作者人格覆盖本人 |
| 事实与隐私 | 关键数据、引语、人物、案例有来源或明确缺口 | 编造；保密材料靠模糊化公开；假审核/假引用 |
| 论证与长度 | 每段有新增作用，机制、反例及必要推演保留 | 只堆观点、强行拉长/压短、固定模板损害原意 |
| 媒介与开头 | 与该媒介阅读/观看和正文承诺一致 | 公众号套秒数；长稿套短钩子；藏答案/假证明 |
| 内部审查 | 本次实际 reviewer 产物、结论、返工记录 | 主写手自查冒充独立审查；缺审却称通过 |
| 视觉（若请求） | 已加载设计依据，真实渲染/打开，文字与布局检查 | 只有文件无肉眼检查、溢出或错字未修 |
| 项目/同步（若适用） | 来源、项目、版本可追溯，看板回读或标待同步 | 重复建档、工具失败丢稿、假 record_id/假送达 |
| 外部动作（若请求） | 具体平台/版本授权、实际回读、状态准确 | 无授权公开/自动排期，delivery 冒充 published |
| 反馈（若请求） | 数据与目标匹配、未知项标缺失、候选改进 | 小样本定因果、自动改长期规则/回复私信 |

## 独立复核记录

```text
scope:
requested_deliverables:
actual_artifacts:
checks: {name: pass | fail | not_applicable | unverified}
blockers:
majors:
rewrite_plan:
reviewer:
review_evidence:
decision: accept | quarantine | block
```

accept 在内容审查中仅表示已检查范围通过，不是用户接受终稿、原始 skill_gate 通过、视觉验收或平台发布。升级检查分别记录结构检查、引用/依赖、规则冲突、实际文本回放、独立 review、原指定 gate、真实平台路径是否执行，不能相互替代。

若原指定 gate 不可用，明确记录错误；不以自行命名的检查器伪造原门禁。候选包先保留隔离，按上游 skill-synthesizer 的批准/门禁要求处理激活。验证证据必须绑定本次候选文件的摘要，修改后重验受影响项。
