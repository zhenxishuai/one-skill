# One 渠道写法

材料取用与声音校准见 [正文生产](../../one-produce/references/writing.md)，已读内容不重复加载。这里仅规定渠道表达，只执行本次相关路径。以下是包内生产方法，不依赖另装公众号、口播或小红书 Skill。平台实时限制影响制作或投递时，查官方当前规则，不把旧字数、尺寸和算法猜测当常量。

## 公众号

1. 判断输入：一句想法先找能成立的具体问题；多份素材找共同判断；半稿定位卡点；成稿只改授权部分。已有材料不重做访谈。
2. 按材料选择推进方法：商业判断把动作、利益与代价的因果讲清；人物故事沿真实选择及后果推进；热点先界定新事实改变了什么、没改变什么；创始人笔记保留当时怎么认识和修正。方法可组合，不必先给用户分稿型。
3. 让具体来源承担段落作用。把泛泛的“有价值、有效率”落到本题真实动作、时间、责任或成本；没有数字就解释关系，不造账。
4. 用具体人事或问题进场，尽快给判断。安排足够解释和真实例子，让后一段从前一段的疑问中生长。不要把内部提纲、评分、卡号或模板名称写入正文。
5. 完成全文再收紧语言；看手机阅读时段落是否易读，逻辑是否仍完整。是否用小标题取决于文章，不固定段数、素材数或模型数。
6. 对照原文和来源审查，必要时局部返工。默认交付完整待审正文；标题、封面、排版和平台投递按用户请求增加。

## 短中长口播

1. 先定这段要让谁听懂什么。行动实战稿需要真实动作与检验点；观察判断稿可以推演但须标边界；信任故事稿需要真实经历，不强制产品 CTA。
2. 单一动作选短稿；需要例子与解释就展开；多变量问题保留概念辨析、反例和递进链。用户指定时长则围绕其目标取舍，无法同时讲全时明确删减范围，不注水、不压掉关键前提。
3. 中长稿开头在约 15–30 秒内给观看理由，已有真实可展示证明时前置。短稿直接指向具体问题或结果，全文兑现承诺；不得编造亲测画面。
4. 一口气讲得通：短句用于转折和判断，必要长句解释机制，抽象词落到动作或例子。读出或做分段口述检查，拗口处重写。文本估时标为估算，不能冒充实测语速。
5. 用户要稿和板书时，交完整稿、一张讲述板和少量拍摄提示。讲述板保留能让作者接着讲的关键因果、例子提示与收口，不只剩关键词，也不把逐字稿缩小塞进去。每个增写/圈画动作对应稿件具体段落；读到那个位置应能从板书找回下一步，不增加稿中没有的事实。
6. 概念或中长论证稿检查听者能否说明概念的边界、关键机制、会改变结果的变量，以及判断何时失效；只在本题相关时检查成本与利益。缺哪一环补哪一环，不强制七问或几层结构。
7. 用户说看板书自己讲时，讲述板放前台，完整稿留作论证依据。文字板书可以直接交；需要图片时进入 one-design。独立审查缺失则整套标待审，不能说可拍可发。

## 小红书

1. 单篇写作先看目标读者会搜什么、遇到什么具体问题、能保存带走什么；账号定位只在用户明确请求或重大方向不明时做。
2. 由材料选择经验叙述、步骤、清单、对照或判断。每项有具体动作或证据，不把所有内容做成万能清单。用户材料中的体验不能放大成普遍效果。
3. 默认一个标题。标题、封面承诺和前几行围绕同一件事，正文完整兑现。关键词自然进入，不堆标签，不强制 emoji、称呼、互动诱导或固定备选数量。
4. 只要文字就交文字；要图文则按论证分页面，每页一个可读的重点，跨页仍是同一条主线，转 one-design 制作并检查。
5. 平台数据缺失不能猜限流或宣布算法规律。事实、隐私、广告承诺与原意按同一标准审查。

## X 与其他短文本

先给能独立成立的具体判断，必要时用短线程逐步解释；每条提供新增信息，避免把长文机械按字数截断。语言、长度和是否附链接按用户目标与当前平台限制核验。不得为了引流虚构成绩或自动私信。

## 内容与服务连接

只有任务明确推动行动时，检查：面向谁、解决什么、用何证明、下一步是什么、实际承接是否存在。没有服务细节就标缺口，不编价格和交付承诺。内容地图可以围绕读者连续出现的问题组织，但不自动安排发布计划。
