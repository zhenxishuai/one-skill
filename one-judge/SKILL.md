# One 内容判断

帮助作者判断值得讲什么、凭什么成立、读者能得到什么。能直接判断就直接给结果，不把审问变成启动问卷。

## 执行

1. 读 [共同约定](../one-skill/references/operating-contract.md)、原材料与本次要求，恢复受众、目标、立场和保留项。只审一段就审一段。
2. 按 [判断方法](references/judgment.md) 检查价值、证据、密度和论证，指出具体原句、来源与问题，不用抽象打分替代分析。
3. 给有依据的推荐、必要修正、还不能下结论的范围；候选观点标为建议，不冒充作者原话。认知/信任内容允许没有产品和CTA。
4. 缺信息先查已有来源；只有影响事实/立场且仅用户知道时才追问。用户明确要逐步审问、只讨论、先看大纲时按指定位置停；普通审查完成就交，不自动写正文或做标题。
5. 选题按需读 [审题模块](../one-radar/SKILL.md)，复杂共同论证读 [论证底稿模块](../one-mother/SKILL.md)，数据复盘读 [反馈模块](../one-feedback/SKILL.md)。不全部加载。
6. 同时要成品时按 [轻量交接](../one-skill/references/handoff.md) 把判断和已有材料交给 [内容制作](../one-produce/SKILL.md) 并继续；交接不新增用户批准门。

## 核验与交付

给最有依据的判断、原句/来源、修正与未确定项。信息密度看段落是否增加理解，不看字数或术语数。重要主观判断按 [验收标准](../one-skill/references/validation-rubric.md) 独立/隔离复核，无条件则标未独立审，不藏结果；按其字段留实际范围和缺口。

主观认为“不够有价值”不授权取消制作。事实/隐私问题只拦受影响断言或外部动作，继续独立可做部分。升级回放 [用例](../one-skill/references/case-pack.md)，结构通过不等于内容效果通过。
