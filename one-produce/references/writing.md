# 从材料到可用正文

只在起草、实质改写或完整母稿时读取。纯排版、制作既定文字图片、发送定稿不走以下流程。

## 先知道用什么写

1. 锁住本次输入和版本，提取必须保留的原句、数字、限制条件、反例与署名。已有判断直接沿用；只有新立场或关键事实取舍才回到判断侧。
2. 从材料说明作者怎样知道这件事：本人亲述、实际调查、可核实来源或明确推断。没有经历就不补经历，不把研究资料写成作者在客户现场见过。
3. 用户配置且允许检索的知识库先做相关召回。打开候选材料的实际正文，不凭标题或摘要入文；为采用的每条材料标明来源位置、支持的主张和将放入哪一段。无关材料即使精彩也不用，允许没有适用旧卡，不为数量或“使用记录”硬塞。
4. 复杂材料按需复用 [共同论证底稿](../../one-mother/SKILL.md)。只需一句话和两项证据时直接在现有记录整理，不新建研究工程。
5. 从获准的完整样稿里找相近表达，锁住一份主要样稿或明确写法作为本稿参照。学它怎样进场、推进和收尾，不搬题材、句子、个人事实和固定口头禅。无样稿按 [作者标准](../../one-skill/references/authoring.md) 写，标未校准本人声音。

## 让材料进入正文

先形成短写法计划：这次要讲清的一句话、进场材料、每段要解决的问题、所用依据和收口位置。只在内部使用；用户没要求看大纲就继续写。

按 [渠道写法](../../one-skill/references/channels.md) 完成全文。一个材料只能证明它实际证明的部分：金额不能独自证明利润，个人体验不能证明普遍效果，相关变化不能直接证明因果。外部来源有分歧时保留有影响的分歧，不选一句最刺激的就当事实。

写完逐段追问：删掉这一段，读者会少理解什么？没有损失的合并或删除；删掉定义、例子、因果中间环节会造成跳步的，保留或补清楚。材料充足也不机械要求所有稿都讲钱、讲故事、反转或附行动清单。

## 改到能读、能讲

- 首先对照源稿检查新增、遗漏、改义，尤其是“仅限、可能、在某条件下”等限定。要求全局删改时查正文、标题、图文文字和已生成渠道副本，记录受影响版本；不擅自覆盖已发送版本。
- 再查段落推进。后一段接住前一段尚未解释清楚的问题，不用“还有一层”等路标掩盖跳步。删重复结论，保留承担新解释或呼吸作用的重复。
- 同篇前后对照同一份声音参照，检查是否前半像本人、后半变成公文；保留真实原话的力度，不人为加粗口、口头禅、假对话或假时代细节。
- 口播稿逐段检查能否出声说顺，代词是否找得到人、长句是否能接住、例子是否讲得明白。读过文字只能记文本检查，实际读出/录音才记口述实测；估算时长标估算，不能假造语速回执。
- 结尾分别去掉重复总结再读，只在删后仍完整时提前结束。读者尚需知道的限制条件和具体下一步不能为“有力”被删掉。

## 交付

按本次请求交完整正文、指定渠道版本或口播拍摄包。必要来源注释放成品之外，不能用长免责声明替代准确断言。按 [验收标准](../../one-skill/references/validation-rubric.md) 留具体问题和修正证据；完整主观稿的独立复核照常执行，缺审就交完整未审稿。
